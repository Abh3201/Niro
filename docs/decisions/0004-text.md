# 0004: Text is plain, stored as a Y.Text in each shape, and edited in a textarea over the canvas

- Status: accepted
- Date: 2026-10-17
- Code: [`packages/doc/src/yjs.ts`](../../packages/doc/src/yjs.ts), [`packages/engine/src/text-editor.ts`](../../packages/engine/src/text-editor.ts), [`packages/engine/src/text.ts`](../../packages/engine/src/text.ts)

## Decision

- **Plain text, one `Y.Text` per shape,** created with the shape. Rectangles, ellipses, sticky notes and the new text shapes hold text; lines don't. Board format version 2; older Niro versions open these boards read-only, as [the format rule](../../packages/doc/src/shape.ts) says.
- **Edited in a `<textarea>` laid over the shape,** transparent, rotated and scaled with it, while the canvas skips that shape's text. The browser provides the cursor, selection, spell check, input methods and accessibility.
- **Drawn on the canvas** with Niro's own line breaking, matched to the browser's `pre-wrap` rules, and font sizes found by search so text fits its shape.
- **The store reports text deltas** (`ShapeChange.textEdits`), so an editor keeps its cursor on the right characters while others type. Comparing old and new text instead put two people's letters inside each other's words in 7 of 8 test runs ([the write-up](../learning/text.md#keeping-your-cursor-while-someone-else-types)).

## What this gives up

- **No rich text.** Bold, lists and links would need formatting attributes on the `Y.Text` and an editor that can show them (contentEditable, or a library like ProseMirror with `y-prosemirror`). Plain text keeps the CRDT, the layout and the editor small; rich text can come later as format version 3.
- **Two layout engines must agree.** The canvas wraps lines itself and the browser wraps the textarea. They follow the same rules, but measuring differs slightly, so text can shift by a pixel, rarely by a line, when editing ends.
- **One size for text shapes.** Resizing one changes where it wraps, not how big its letters are.

## Alternatives considered

- **`contentEditable` over the canvas:** what rich text would need, but much harder to keep in step with a CRDT (the browser rewrites the DOM in its own ways). Not needed for plain text.
- **Draw the cursor and selection on the canvas, and read keys directly:** full control, but no input methods, spell check or screen readers without reimplementing them.
- **Store text as a plain string field:** last writer wins, so two people typing in one sticky would lose one person's text. The `Y.Text` costs a few bytes per shape.
